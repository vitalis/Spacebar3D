# HIG audit, November 2026 (macOS 26, Liquid Glass)

Scope: the app (main window, Settings, Acknowledgements, viewer windows, menus) and the Quick Look
extension, checked against the Human Interface Guidelines as published on 2026-11-16.
Evidence: source as of this date, screenshots `/tmp/p3d-icon/store/01…09-*.png` and `ql-glass.png`.
No source was changed.

Confidence tags:
- **[V]**: the rule was read on the HIG page (or Apple developer doc) today and is quoted.
- **[M]**: the rule is from memory or inferred; verify before acting.
- **[R]**: the behavior needs checking at runtime; the code suggests a problem but does not prove it.

HIG pages used (fetched through `developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json`):
the-menu-bar, keyboards, materials, color, toggles, accessibility, voiceover, offering-help,
focus-and-selection, settings, windows, popovers, pointing-devices, alerts, typography; plus the
SwiftUI article "Applying Liquid Glass to custom views".

## 3. Checked and compliant

- **App menu.** Order: About first, then Settings… (⌘,). Open… has its ellipsis; New is correctly replaced for an app with nothing to create. Open Recent lists file names (not paths), newest first, up to ten, with Clear Menu. [V]
- **Shortcuts.** None of ⌘1–8, ⌘0, ⌘−, ⌥⌘1–6, ⌥⌘G, ⌥⌘R collides with a row of the standard table. ⌥⌘8 (screen zoom) is avoided. Plain arrows are taken only by the model with focus, only in the app, so sliders keep theirs and Quick Look keeps file navigation. [V]
- **Alert.** "“X” could not be opened." is a complete sentence in sentence case with a period. OK is used only on an informational alert. [V]
- **Reduce Motion.** Respected everywhere checked: the camera opening and preset moves jump; the arrival has no offset or blur (fade only, as the HIG suggests); the Signal stops breathing; the loading mark is paused; the opening light is off; springs settle; moving textures and the hologram stop; auto-rotate does not start by default. [V]
- **Reduce Transparency.** Glass is replaced by the solid surface, in panels and popovers. [V for the setting's existence; the replacement look is the owner's]
- **Contrast on the solid palette** (WCAG relative luminance, computed from `NeonGarden.swift`; ratios on `background` / `surface` / `surface-3`):
  - text #F1F4F0: 17.3 / 15.9 / 12.7
  - text-2 #AEB9B0: 9.5 / 8.7 / 7.0
  - text-3 #8A978D: 6.3 / 5.8 / 4.6
  - mint #A6E3A7: 12.9 / 11.9
  - info #B8D3FF: 12.6 / 11.6
  - danger #FF3D3D: 5.5 / 5.0
  - Signal label on chartreuse: 16.4
  - Tape heading text on mint-2: 8.7; on warm-2: 5.7; on info: 12.6
  - All pass 4.5:1. The disabled glyph (text-3 at 55% over surface, about #525F57) is 2.7:1, which is allowed for disabled controls. [V for thresholds]
- **Not by color alone.** Gizmo far ends are hollow dashed rings with near ends lettered. On-state is a well, an edge, and semibold weight. Disabled is a dashed edge. [V]
- **Hit targets.** Canvas controls are 32 pt, above the 28 pt default. The exception is the gizmo (#12). [V]
- **Type.** Nothing is under 10 pt (statistics labels are 10 pt heavy). [V]
- **Symbols.** All canvas icons are SF Symbols, each with a VoiceOver label. Decorative art (`NeonMark`, tape, cord, graph paper) is hidden from VoiceOver. Loading is announced as "Loading". [V]
- **Button toggles.** Icon toggles change their background for state, as the Toggles page describes for button-style toggles. [V]
- **Settings.** Reached from the app menu. System controls in the user's accent color (`.tint(nil)`). Labels end in colons. Restore Defaults is present. A save failure is reported. [V for the menu rule]
- **Notice.** One caution symbol, a short fragment title with no period, "Show Textures…" with an ellipsis, and the open panel with a clear message and an "Allow" prompt. [V]
- **Glass placement.** Glass is used only on floating controls over the content, never on the model or the room (except #10). Regular variant (correct over varied content). [V]
- **Popovers.** One at a time; closing loses nothing, since changes apply immediately. [V]
- **Quick Look.** Controls give way at small sizes (under 480×340) rather than covering the model. Nothing depends on ⌘ keys. [V for intent; R for key delivery]
- **Info.plist.** Document types use role Viewer with rank Alternate, so the app never takes over as default. The category is graphics-design. [M for convention]
- **Window titles.** The file name. [M]

## 4. Owner decisions that depart from HIG (one line each)

- **Always-visible controls.** No departure: the HIG does not require auto-hiding on Mac.
- **Dark only.** Fine for the viewer. The Settings, main, and Acknowledgements windows are also forced dark. That is a further step from "make sure all your app's colors work well in light, dark, and increased contrast contexts" (Color, [V]).
- **Tinted glass on every panel.** The Color page says "Refrain from adding color to the background of multiple controls" ([V]). The tint is a dark legibility wash rather than emphasis, so this is a mild departure.
- **Mint glyphs for "on" on glass.** "Apply color sparingly… to symbols or text on the material" ([V]). Acceptable as a status indicator, which the page allows.
- **`.tint(mint)` in the viewer** (`NeonGarden.swift:177`). This overrides the user's accent color on system controls inside the popovers (checkboxes, pop-up, slider fill). The HIG says the user's chosen accent replaces the app's ([V]).
- **App name and icon.** Not assessed.

## 5. Could not verify, and why

- **Key delivery to the extension.** Whether Quick Look passes Space, Tab, or the arrows to the extension's view, and so whether #2 is real. This needs a run in Finder with an animated model.
- **What VoiceOver says.** The output for `GardenToggleStyle`, `GardenSegments`, and the gizmo (#9), and whether the custom focus ring ever appears under Full Keyboard Access (#8). This needs Accessibility Inspector on a running build, in both hosts.
- **Contrast over glass.** Regular glass adapts its luminosity to what is behind it, so ratios depend on the model. Only the solid palette was measured. The screenshots, including the near-white Sketch render in 06, look legible.
- **Settings window title.** Whether SwiftUI titles the single-pane Settings window "Spacebar 3D Settings", as the Settings page asks. Read the running window.
- **⌘= for Zoom In** (#14) and full-screen capability of the AppKit viewer windows (#22). The green button is present in the screenshots; the View menu was not seen.
- **Pages not fetched.** Writing, Dark Mode, Onboarding, Launching, Sliders, Going full screen, App icons. The HIG has no Quick Look page. Findings that lean on these are marked [M].
- **App Review.** No guideline was found that the app plainly breaks. The app has real functionality beyond the extension, which matters for 4.2. This is judgment, not a check against the current App Review Guidelines.
- **Prior memories.** The memory store's recall output was too large to read without a shell, so none of it was used. Everything above comes from the repository and the pages listed.
