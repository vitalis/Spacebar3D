<a id="requirements"></a>

## Требования

| Требование | Примечания |
| :--- | :--- |
| Mac с чипом Apple и macOS 26 или новее | Проект и Assimp собираются для `arm64`; вариант для Intel не создаётся. |
| Полный Xcode с SDK macOS 26 или новее | Одних Command Line Tools недостаточно. Текущая локальная среда разработки использует Xcode 27.0. |
| XcodeGen | Генерирует проект Xcode из `project.yml`. |
| CMake и Ninja | Собирают нативную зависимость Assimp. |
| Python 3 | Запускает проверку согласованности переводов. |
| Сертификат и ключ для подписи разработки | Нужны установленному приложению, расширению и их общей App Group. См. ниже. |

```bash
brew install xcodegen cmake ninja
xcodebuild -version
xcrun --sdk macosx --show-sdk-version
```

Если оболочка использует Command Line Tools или другую установку Xcode, перед сборкой укажите полный Xcode:

```bash
export DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer
```

`build.sh` также обнаруживает эту стандартную установку, когда `xcode-select` указывает на Command Line Tools. При прямом вызове `xcodebuild` и сборке зависимостей нужно заранее выбрать правильный каталог разработчика.

<a id="build-local"></a>

## Локальная сборка

<a id="configure-signing"></a>

### Настройка подписи

Конфигурация в репозитории использует команду разработчиков из [`project.yml`](../../project.yml). Для своей команды:

1. Задайте `DEVELOPMENT_TEAM` и подходящие идентификаторы bundle в `project.yml`.
2. Настройте App Group для команды. Укажите один и тот же идентификатор в [`Spacebar3D.entitlements`](../../Spacebar3D/App/Spacebar3D.entitlements), [`Spacebar3DExtension.entitlements`](../../Spacebar3D/Extension/Spacebar3DExtension.entitlements) и `ViewerSettings.appGroup` в [`ViewerSettings.swift`](../../Spacebar3D/Shared/ViewerSettings.swift).
3. Убедитесь, что Xcode может использовать сертификат Apple Development команды и необходимые файлы provisioning. После изменения конфигурации заново сгенерируйте проект.

Текущая App Group: `V3AQWQ8JMY.com.vitalis.Spacebar3D`. Смена только команды в команде сборки не обновляет этот идентификатор. Неподписанная сборка или подпись ad hoc не заменяют проверку регистрации расширения и доступа к общему контейнеру.

<a id="build-the-app"></a>

### Сборка приложения

```bash
./scripts/build.sh
```

Скрипт собирает Assimp, если его framework отсутствует, запускает XcodeGen и собирает схему `Spacebar3D` в конфигурации Release. Результат:

```text
build/Build/Products/Release/Spacebar 3D.app
```

Для первой сборки нужен доступ к сети для загрузки зависимостей. [`build-assimp.sh`](../../scripts/build-assimp.sh) фиксирует Assimp на `v6.0.6` и перед компиляцией проверяет полный SHA коммита `a79ff6bbce54d3e01186a918dc6374ed55317426`. Создаётся статический arm64 XCFramework с импортерами FBX и 3DS, без экспортеров и Draco.

Повторно запускайте скрипт при смене закреплённой ревизии. `build.sh` проверяет только наличие framework, а не соответствие текущей ревизии. Чтобы использовать локальную копию исходников на нужном коммите:

```bash
ASSIMP_SRC=/path/to/assimp ./scripts/build-assimp.sh
```

<a id="register-and-exercise-quick-look"></a>

### Регистрация и проверка Quick Look

1. Скопируйте собранное приложение в `/Applications` и один раз запустите эту копию.
2. Включите **Spacebar 3D** в **Системные настройки → Основные → Объекты входа и расширения → Quick Look**.
3. Выберите поддерживаемый файл в Finder и нажмите пробел.
4. Откройте тот же файл через **Файл → Открыть…** в приложении, чтобы проверить оба варианта запуска.

Если регистрация устарела, обновите кеш и попробуйте файл GLB:

```bash
qlmanage -r
qlmanage -r cache
qlmanage -p /path/to/model.glb
```

Для OBJ, STL, PLY, USD и USDZ macOS может выбрать собственный просмотрщик Apple. Это не доказывает неисправность расширения. Используйте приложение или необязательную смену обработчика, описанную в [README](README.md#help).

<a id="development"></a>

## Разработка

Для редактирования и отладки в Xcode:

```bash
./scripts/build-assimp.sh
xcodegen generate
open Spacebar3D.xcodeproj
```

Собирайте Assimp один раз на ревизию зависимости и заново генерируйте проект при изменении `project.yml`. Git игнорирует `.xcodeproj`, оба сгенерированных `Info.plist`, результаты сборки и `Vendor/Assimp.xcframework`. Меняйте исходный YAML, а не сгенерированный проект или списки свойств.

Инкрементальная Debug-сборка из терминала:

```bash
xcodebuild -project Spacebar3D.xcodeproj -scheme Spacebar3D \
  -configuration Debug -destination 'platform=macOS' \
  -derivedDataPath build build
```

`SKIP_XCODEGEN=1 ./scripts/build.sh` повторно использует существующий сгенерированный проект и по-прежнему собирает Release. Используйте этот режим только при соответствии проекта YAML-файлу.

<a id="capture-media"></a>

### Запись видео и создание снимков экрана

Выполните описанные выше требования к сборке и запустите скрипт в графическом сеансе macOS. В Системных настройках разрешите запись экрана приложению, из которого запускаете скрипт.

Если модель ссылается на внешние текстуры, материалы или геометрию, сначала откройте её в обычном приложении Spacebar 3D. Нажмите кнопку с папкой в просмотрщике и разрешите доступ к папке с этими файлами. Версия для записи использует сохранённое разрешение. При открытии одного лишь файла модели сопутствующие файлы могут остаться недоступными.

```bash
brew install ffmpeg
./scripts/capture-media.sh /path/to/model.glb
```

Скрипт собирает и запускает отдельную копию Spacebar 3D с включённой функцией записи. Чтобы использовать уже собранную с этой функцией копию, укажите путь к её пакету `.app` в переменной `SPACEBAR3D_APP`. По умолчанию скрипт создаёт новую папку в `build/media-captures/`. Чтобы выбрать папку для результатов, передайте свободный путь вторым аргументом.

Общедоступное видео для Mac App Store, `preview.mp4`, длится 30 секунд и показывает все стили отображения, доступные для модели. Разрешение видео составляет 1920 × 1080, частота составляет 30 кадров/с. Скрипт также сохраняет четыре PNG размером 2560 × 1600 и `demo.gif`. Если у модели не менее трёх стилей, GIF использует тот же 15-секундный монтаж, что и зацикленное видео со стилями. Если стилей меньше, в GIF попадает видео `preview.mp4` с исходной скоростью. Для первого снимка выбирается вид «Текстуры», если он доступен (`01-textured.png`), или «Сплошной» (`01-solid.png`). Остальные снимки называются `02-wireframe.png`, `03-normals.png` и `04-hologram.png`.

<a id="capture-feature-loop"></a>

### Запись зацикленного видео со стилями

С теми же настройками записи можно создать зацикленное видео на 15 секунд с частотой 30 кадров/с. Модель должна поддерживать не менее трёх стилей отображения. Приоритет у стилей «Сел-шейдинг», «Воксельная графика» и «Голограмма».

```bash
./scripts/capture-feature-loop.sh /path/to/model.glb
```

По умолчанию скрипт сохраняет `feature-loop.mp4` в новой папке в `build/media-captures/`. Чтобы выбрать папку для результата, передайте свободный путь вторым аргументом.

<a id="capture-screenshots"></a>

### Создание снимков экрана для App Store

С теми же настройками записи можно создать четыре перечисленных выше снимка PNG в sRGB размером 2560 × 1600.

```bash
./scripts/capture-screenshots.sh /path/to/model.glb
```

По умолчанию скрипт сохраняет файлы в новой папке в `build/media-captures/`. Чтобы выбрать папку для результатов, передайте свободный путь вторым аргументом.

<a id="capture-app-review"></a>

### Запись закрытой демонстрации для App Review

Установите и запустите обычное приложение Spacebar 3D и включите его расширение Quick Look. Выберите модель, которая открывается в Quick Look в Finder с интерактивным предпросмотром. Перед записью закройте предпросмотр Quick Look в Finder и окна отдельного просмотрщика с тем же именем файла. Понадобятся описанное выше разрешение на запись экрана, инструменты командной строки Swift и FFmpeg с фильтрами `drawtext` и `subtitles`. Оставьте терминал на виду и следуйте его подсказкам. Оставьте файл выделенным в Finder и при необходимости переключитесь в режим списка. По подсказке нажмите пробел и дважды поверните модель или измените масштаб. По подсказке нажмите кнопку открытия в Spacebar 3D. Если macOS покажет меню приложений, выберите Spacebar 3D. Если кнопки нет, закройте Quick Look и откройте тот же файл в Spacebar 3D через **Файл → Открыть…**. Дважды поверните модель или измените масштаб в отдельном просмотрщике.

```bash
SPACEBAR3D_REVIEW_ANIMATION_MODEL=docs/app-store/Spacebar3D-Review-Model.glb \
  ./scripts/capture-app-review.sh /path/to/model.fbx build/media-captures/app-review
```

Скрипт добавляет поясняющие надписи и сохраняет `app-review.mp4` в новой папке в `build/media-captures/`. Чтобы выбрать папку для результата, передайте вторым аргументом свободный путь. Задайте `SPACEBAR3D_REVIEW_APP`, если приложение установлено по пути, отличному от `/Applications/Spacebar 3D.app`.

После записи по подсказкам скрипт записывает главы об управлении просмотрщиком, настройках, справке и конфиденциальности. В примере для главы о воспроизведении используется анимированный образец. Задайте `SPACEBAR3D_REVIEW_CAPTURE_APP`, чтобы использовать уже собранное приложение для записи. По умолчанию скрипт собирает его в описанной выше среде разработки.

Если уже есть запись шагов в Finder и просмотрщике, главы можно добавить с помощью `capture-review-features.sh`. См. `--help`.

<a id="tests"></a>

## Тесты

Соберите Assimp до разрешения зависимостей пакета или запуска любого из двух вариантов тестирования.

<a id="full-xcode-suite"></a>

### Полный набор Xcode

Это основная команда регрессионной проверки. Она включает тесты исходников приложения, общего кода и расширения, а также все девять тестовых targets пакета, объявленных в `project.yml`.

```bash
xcodegen generate
xcodebuild test -project Spacebar3D.xcodeproj -scheme Spacebar3DTests \
  -destination 'platform=macOS' -derivedDataPath build
python3 scripts/check-localizations.py
```

Для выборочного запуска добавьте селектор `-only-testing`, например:

```bash
xcodebuild test -project Spacebar3D.xcodeproj -scheme Spacebar3DTests \
  -destination 'platform=macOS' -derivedDataPath build \
  -only-testing:ViewerUITests/NativeViewerInputTests
```

Xcode сохраняет пакеты `.xcresult` в `build/Logs/Test/`.

<a id="package-only-tests"></a>

### Только тесты пакета

Они не включают тесты исходников хостов из `Spacebar3DTests`:

```bash
xcrun swift test --package-path Packages/Spacebar3DKit
```

Два теста больших моделей включаются явно через `P3D_LARGE=1`. Один создаёт тестовый STL-файл размером около 100 МБ. Для запуска этого бенчмарка:

```bash
P3D_LARGE=1 xcrun swift test --package-path Packages/Spacebar3DKit \
  --filter LargeModelTests
```

<a id="what-the-tests-establish"></a>

### Что проверяют тесты

- Тесты настроек используют явно заданное временное хранилище. При изменении правил добавляйте случаи нормализации в [`settings-vectors.json`](../../testdata/settings-vectors.json).
- Тесты импортеров создают небольшие файлы и проверяют некорректные и обрезанные входные данные.
- Тесты рендерера рисуют вне экрана и проверяют пиксели; им нужно работающее устройство Metal.
- Тесты просмотрщика проверяют нативный ввод, метаданные универсального доступа, команды, компоновку и элементы SwiftUI, в том числе через ViewInspector.
- Проверки локализации охватывают исходные ключи, записи каталога и подстановки. Тесты пакета также проверяют скомпилированные языковые ресурсы.

Схема Xcode компилирует исходники хостов в тестовый bundle. Она не запускает подписанное приложение в его рабочей песочнице. Успешные тесты не подтверждают регистрацию Quick Look, разрешения на папки, речь VoiceOver или поведение нотарифицированной загрузки. Для таких изменений дополнительно проверяйте установленное подписанное приложение и расширение Finder.

<a id="how-it-works"></a>

## Устройство проекта

```text
Finder → Quick Look extension ─┐
                              ├─ ViewerFactory → NativeViewer
App → model window ───────────┘                      │
                                     ImportRouter → ModelScene
                                                     │
                                           RenderMetal / MTKView
                                           + SwiftUI controls
```

Оба хоста используют локальный пакет `Spacebar3DKit`. Импорт выполняется вне главного потока; нативный просмотрщик согласует рендеринг и элементы управления.

| Область | Назначение |
| :--- | :--- |
| `Spacebar3D/App/` | Начальная настройка, параметры, окна моделей, регистрация приложения по умолчанию, меню, справка и благодарности. |
| `Spacebar3D/Extension/` | Жизненный цикл предпросмотра Quick Look. |
| `Spacebar3D/Shared/` | Создание просмотрщика и общие настройки. |
| `Packages/Spacebar3DKit/Sources/ModelCore/` | Данные сцены, определение формата, анимация, топология и локализация. |
| `…/Sources/ImportRouter/` и `…/Sources/Import*/` | Выбор обработчика формата и чтение файлов. |
| `…/Sources/RenderMetal/` | GPU-сцена, камера, затенение и рендеринг. |
| `…/Sources/ViewerUI/` | API просмотрщика, нативный ввод, элементы SwiftUI и разрешения на папки. |
| `…/Sources/CZstd/` | Включённый в проект декодер Zstandard для сжатых файлов Blender. |
| `Spacebar3DTests/` и `Packages/Spacebar3DKit/Tests/` | Тесты исходников хостов и пакета. |
| `docs/<language-code>/README.md` | Девять переводов README. |
| `docs/<language-code>/DEVELOPMENT.md` | Девять переводов руководства разработчика. |

Нативные обработчики Swift читают STL, PLY, OBJ, 3MF, glTF/GLB, VRM/VRMA и Blender. Model I/O обрабатывает USD, а Assimp обрабатывает FBX и 3DS. `FormatDetector` проверяет начальные байты, а для неоднозначных текстовых форматов также расширение файла. Типы документов и `QLSupportedContentTypes` объявлены в `project.yml`.

Файлы только с анимацией и поддерживаемым скелетом могут отображаться как схематичный скелет. Аватар по умолчанию не поставляется. Поддержка форматов намеренно уже, чем в полноценном DCC-приложении. При изменении обработчиков обновляйте ограничения в README.

<a id="implementation-notes"></a>

## Примечания к реализации

<a id="sandbox-and-related-files"></a>

### Песочница и связанные файлы

Оба targets используют App Sandbox и доступ только для чтения к выбранным пользователем файлам. Ни у одного нет сетевого entitlement или временного исключения из песочницы.

Открытие модели не даёт неограниченного доступа к соседним файлам. Оба хоста могут предложить **Показать модель…**, **Показать материалы…** или **Показать текстуры…**, чтобы запросить папку. Приложение также поддерживает определённые сопутствующие файлы материалов с тем же именем, например `ship.mtl` рядом с `ship.obj`, через механизм связанных файлов.

[`FolderGrants.swift`](../../Packages/Spacebar3DKit/Sources/ViewerUI/FolderGrants.swift) сохраняет разрешения приложения как закладки с областью безопасности. Quick Look хранит собственные обычные закладки и читает копии, обновлённые приложением в общем контейнере. Разрешение, выданное только Quick Look, нужно обновить после перезапуска Mac. Запуск приложения обновляет сохранённые им разрешения для расширения. Чтение ограничено разрешёнными папками и их содержимым, включая вложенные папки.

<a id="settings"></a>

### Настройки

`ViewerSettings` хранит `viewer-settings.json` в контейнере App Group. Приложение записывает файл, новые просмотрщики загружают нормализованные значения. При неверных, слишком больших или отсутствующих настройках используются значения по умолчанию. Миграции из старого расположения вне контейнера, `~/Library/Application Support/Spacebar3D/`, нет.

<a id="input-and-accessibility"></a>

### Ввод и универсальный доступ

Стрелки вращают камеру вокруг модели, а Shift-стрелки сдвигают её только тогда, когда область модели отдельного приложения обрабатывает клавиатуру. Пробел запускает или приостанавливает воспроизведение в этой области. Это не глобальное сочетание меню; оно не должно перехватывать активацию кнопок или ползунков в фокусе. Quick Look сохраняет закрытие по пробелу. Действия меню и универсального доступа дают альтернативу жестам указателя.

Меняя элементы управления, проверяйте фокус клавиатуры, узкие окна, длинные переводы, увеличение контрастности и уменьшение прозрачности. Реальные объявления VoiceOver нужно прослушивать отдельно от проверок дерева универсального доступа.

<a id="localization-and-documentation"></a>

### Локализация и документация

Общий каталог строк `Packages/Spacebar3DKit/Sources/ModelCore/Resources/Localizable.xcstrings` предоставляет десять языков приложению и расширению. Требования к полным строкам, подстановкам, скомпилированным ресурсам и проверке компоновки описаны в [LOCALIZATION.md](../LOCALIZATION.md).

Английский README находится в корне, переводы находятся в `docs/<language-code>/`. Руководства разработчика находятся в тех же языковых папках, английский оригинал находится в `docs/DEVELOPMENT.md`. Согласовывайте ограничения форматов, управление, установку, поведение разрешений и процедуры разработки во всех версиях.

<a id="troubleshooting"></a>

## Решение проблем

| Симптом | Проверка |
| :--- | :--- |
| При разрешении пакета отсутствует Assimp | Выполните `./scripts/build-assimp.sh` с доступными полным Xcode, CMake и Ninja. |
| Ошибка подписи или недоступны общие настройки | Проверьте сертификат, команду, bundle ID и совпадающие идентификаторы App Group. Переменная окружения сама по себе не переписывает entitlements. |
| Изменения исчезают после генерации | Меняйте `project.yml`, а не сгенерированные `.xcodeproj` или `Info.plist`. |
| Расширение отсутствует или загружается старая версия | Запустите нужное установленное приложение, включите расширение, проверьте регистрацию и обновите Quick Look. Не путайте установленную копию с копией в каталоге сборки. |
| Открывается просмотрщик Apple | См. ограничения выше; сравните с Файл → Открыть в приложении. |
| Отсутствуют текстуры или геометрия | Прочитайте сообщение, разрешите папку модели и проверьте ограничения формата и сопутствующие файлы. |
| Ошибка GPU-теста | Убедитесь в доступности Metal и изучите сбой. Недоступная GPU не означает успешную проверку рендеринга. |

Проверьте регистрацию расширения и просмотрите поток его логов:

```bash
pluginkit -m | rg -i spacebar3d
log stream --predicate 'process == "Spacebar3DExtension"'
```

Первая команда использует `rg` из ripgrep; можно заменить его на `grep -i spacebar3d`. В другом терминале выполните `qlmanage -p /path/to/model.glb`. Отклонённая модель должна показывать ошибку в предпросмотре. Прежде чем менять подпись или разрешения, определите, связана ли проблема с импортом, рендерингом, доступом или выбором расширения.

<a id="distribution-signing--notarization"></a>

## Распространение, подпись и нотарификация

Скрипты реализуют **прямое распространение через Developer ID в виде DMG**. Они не архивируют, не экспортируют и не загружают сборку для Mac App Store. Для магазина нужен отдельный процесс подписи, архивации, экспорта и отправки в App Store Connect.

Для прямого распространения используйте Developer ID Application и нотарификацию. [Руководство Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) описывает требования к подписи и сервису. Цены участия здесь намеренно не дублируются.

<a id="manual"></a>

### Вручную

После настройки соответствующих идентификаторов команды и App Group:

```bash
SIGN_IDENTITY="Developer ID Application" DEVELOPMENT_TEAM=YOUR_TEAM_ID \
  ./scripts/build.sh
```

При заданном `SIGN_IDENTITY` скрипт выбирает ручную подпись, передаёт `DEVELOPMENT_TEAM`, добавляет защищённую метку времени и отключает добавление базовых отладочных entitlements. Hardened Runtime включён в `project.yml`. Без `SIGN_IDENTITY` используется подпись разработки из конфигурации проекта.

Для локальной нотарификации предпочтителен профиль Связки ключей. Интерактивно сохраните учётные данные через `notarytool`, затем вызовите скрипт с именем профиля:

```bash
xcrun notarytool store-credentials "spacebar3d-notary"
NOTARY_KEYCHAIN_PROFILE="spacebar3d-notary" ./scripts/notarize.sh
```

Скрипт принимает необязательный путь к приложению:

```bash
NOTARY_KEYCHAIN_PROFILE="spacebar3d-notary" \
  ./scripts/notarize.sh "/path/to/Spacebar 3D.app"
```

Способ аутентификации выбирается в следующем порядке:

| Способ | Переменные |
| :--- | :--- |
| Профиль Связки ключей | `NOTARY_KEYCHAIN_PROFILE` |
| Ключ API App Store Connect | `NOTARY_KEY_PATH`, `NOTARY_KEY_ID`, `NOTARY_KEY_ISSUER` |
| Учётные данные Аккаунта Apple | `APPLE_TEAM_ID`, `NOTARY_APPLE_ID`, `NOTARY_PASSWORD` |

Последний способ передаёт пароль приложения аргументом `notarytool`. Профиль Связки ключей позволяет избежать этого на общем компьютере. Не храните ключи подписи и учётные данные в репозитории.

`notarize.sh` проверяет подпись приложения Developer ID и создаёт DMG со ссылкой на Applications. Скрипт подписывает DMG с помощью сертификата из подписи приложения, если не задано значение `SIGN_IDENTITY`. Сертификат и закрытый ключ должны быть доступны в связке ключей. Скрипт отправляет DMG в Apple, дожидается одобрения, прикрепляет и проверяет билет нотарификации, затем проверяет решение Gatekeeper через `spctl`. Если все проверки пройдены, он записывает `Spacebar3D.dmg` в корень репозитория. Протестируйте скачанный файл перед распространением.

<a id="automated-github-actions"></a>

### Автоматически через GitHub Actions

[Workflow выпуска](../../.github/workflows/release.yml) использует раннер Apple silicon `macos-26` с Xcode 26. Отправьте или выберите тег в формате `vMAJOR.MINOR.PATCH`, который соответствует `MARKETING_VERSION` и указывает на коммит в `origin/main`.

Workflow генерирует проект, запускает `Spacebar3DTests` и проверку локализации, затем импортирует сертификат подписи. Он собирает приложение с Developer ID, сверяет версии приложения и расширения с тегом, подписывает и нотарифицирует DMG. Перед прикреплением DMG к GitHub Release он удаляет временную связку ключей.

Настройте эти secrets в **фактическом целевом репозитории**:

| Secret | Содержимое |
| :--- | :--- |
| `MACOS_CERTIFICATE` | Сертификат Developer ID Application и закрытый ключ, экспортированные как `.p12` и закодированные в Base64. |
| `MACOS_CERTIFICATE_PWD` | Пароль этого `.p12`. |
| `KEYCHAIN_PASSWORD` | Пароль временной Связки ключей сборки. |
| `APPLE_TEAM_ID` | ID команды подписи. |
| `NOTARY_APPLE_ID` | Аккаунт Apple для нотарификации. |
| `NOTARY_PASSWORD` | Его пароль приложения. |

Явно указывайте репозиторий, например `gh secret set APPLE_TEAM_ID --repo OWNER/REPOSITORY`. Команда запросит значение. Не предполагайте, что локальный `origin` указывает на существующий или нужный репозиторий выпуска.

Перед созданием тега выпуска задайте `MARKETING_VERSION` и `CURRENT_PROJECT_VERSION` в `project.yml`, обновите историю изменений, запустите тесты и проверьте подписанную сборку. Отправка соответствующего тега может опубликовать GitHub Release, если workflow завершится успешно.
